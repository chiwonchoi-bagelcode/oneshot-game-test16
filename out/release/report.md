# 펭귄 슬라이드 — 결과 보고서

> 이 문서는 무엇을 만들었고, 어떻게 확인했고, 무엇을 확인하지 못했는지를 적은 보고서입니다. 확인 방법이 봇·시뮬레이터·헤드리스 브라우저인 항목은 그렇게 적었습니다. **실제 휴대폰과 실제 사람으로는 아무것도 확인하지 않았습니다.**

## 0. 한눈에 보기

- **게임**: `out/index.html` — 세로 화면, 한 손가락(누르기/떼기)만 쓰는 2D 펭귄 비행 게임. HTML5(Canvas 2D + DOM UI)로 만들어 브라우저·웹뷰에서 바로 실행됩니다. 서버 없이 파일로 열어도 동작합니다(`file://`).
- **콘텐츠**: 섬 9개 + 끝없는 하늘(무한 모드), 오늘의 섬(매일 바뀌는 섬), 강화 5종(각 5~10단계), 마을 건물 20개, 출석 선물 7일 주기, 오늘의 할 일, 섬별 목표, 등대(출발 섬 고르기), 막혔을 때 돕는 장치, 결과 화면 팁.
- **출시 준비물**: `out/release/` — 스토어 문구(ko/en), 아이콘, 대표 이미지, 스크린샷 8장(ko, en 따로), 홍보 영상 3종(스토어용·광고용 ko·광고용 en), 자막 4개, 기획서, 이 보고서, 분석 문서, 확인용 페이지 `out/release/index.html`.
- **개발 도구**: 레벨 에디터(`out/editor/index.html`), 개발 빌드 + 디버그 패널(`out/dev/index.html`), 레벨 자동 검증·진행 속도 시뮬레이터·영상 캡처 등 `tools/` 아래 스크립트.

### 개발 도구
- **레벨 에디터** `out/editor/index.html`: 왼쪽 섬 목록, 가운데 캔버스(점·물고기·얼음·바람·간헐천·고리·장식을 끌어서 배치), 오른쪽 속성. [검증]으로 구조 검사 + 봇 클리어율 + 봇 궤적 표시, [테스트 플레이]로 바로 실행, 가져오기/내보내기(JSON).
- **디버그 패널**(개발 빌드에만 있음, 배포 빌드에서는 코드째 빠짐): 물고기 지급, 다음 날로, 건조대 +3시간, 섬 클리어/이동, 강화 최대, 전부 짓기, 부화, 봇 켜기, 안전 영역 흉내, 분석 로그, 초기화.
- **검증·시뮬레이션**: `tools/verify-levels.mjs`(모든 섬 클리어 가능 여부), `tools/run-sim.mjs`(가상 플레이어 진행 속도), `tools/add-first-soar.mjs`(첫 비행 물고기 수확 측정), `tools/qa.mjs`(첫 사용자 흐름 자동 점검), `tools/check-release.mjs`(출시 준비물 규격 검사), `tools/perf.mjs`(CPU 제한 프레임 측정).
- **아트·소리 파이프라인**: 모든 그림은 코드(SVG 생성기 `art/*.mjs`)로 그려 PNG/WebP 아틀라스로 묶고(`tools/pack_atlas.py`, 구조 검사 포함), 모든 소리는 `audio/*.py`로 합성.
- **영상 파이프라인**: 실제 게임을 한 프레임씩 진행시켜 녹화(`tools/capture-lib.mjs`, `shots.mjs`, `trailer.mjs`), 게임이 낸 소리를 프레임 시각 그대로 다시 섞어 영상 소리를 만듦(`tools/trailer_mix.py`).

## 5. 의도적으로 하지 않은 것

- **광고·인앱 결제·상점·유료 재화**: 요구대로 넣지 않음.
- **실제 로그인·클라우드 저장·분석 서버**: 연결할 자리(`src/services/services.js`)만 만들고 실제 서비스는 붙이지 않음. 지금은 기기 안 저장(localStorage)과 콘솔 출력.
- **네이티브 앱 묶음(APK/AAB/IPA)**: 만들지 않음. 스토어에 올리려면 웹뷰 래퍼(예: Capacitor, TWA)로 감싸는 단계가 더 필요합니다.
- **생성형 영상 모델로 만든 컷**: 이 환경에서 쓸 수 있는 영상 생성 모델이 없어 사용하지 않음. 대신 게임 렌더러로 카메라만 연출한 "시네마틱" 한 컷(23.6~25.9초, 슬로모션 클로즈업)을 넣었고, 나머지는 전부 실제 플레이 화면입니다. 게임에 없는 장면은 넣지 않았습니다.
- **스토어 배지(Google Play/App Store 로고)**: 상표 사용 문제로 영상 끝 카드에 넣지 않고 "지금 바로 날아 보세요!" 문구만 넣음.
- **iOS 진동**: iOS 사파리는 진동 API가 없어 진동이 나지 않음(설정에 안내 문구). 오류 없이 넘어가도록만 처리.
- **그리드형 타일셋**: 지형이 곡선(점 보간)이라 격자 타일셋을 쓰지 않음. 대신 눈 결 텍스처·지층 무늬를 지형에 입힘.

## 7. 실제 기기에서 확인하지 못한 것

- **실제 휴대폰(저사양 Android, iPhone)에서의 프레임·발열·배터리**: 헤드리스 Chromium에서 CPU 제한으로만 측정. 헤드리스는 GPU 없이 그려서 실제 기기와 그리는 비용이 다릅니다.
- **소리를 사람이 들어 본 것**: 효과음·음악은 파형·스펙트럼·음량 통계로만 점검했고 사람이 듣고 평가하지 않았습니다. 반복 재생 이음새는 수치로만 확인.
- **앱 전환 후 소리 복귀, 잠금 화면 후 복귀**: 코드(visibilitychange → suspend/resume)만 있고 실제 기기로 확인하지 않음. iOS 사파리의 오디오 잠금 해제 동작도 미확인.
- **진동의 실제 느낌**: 패턴 6종을 코드로 나눴지만 실제 기기에서 세기를 느껴 보지 않음.
- **노치·홈 바 안전 영역**: CSS `env(safe-area-inset-*)`와 흉내 모드(디버그 패널)로만 확인.
- **실제 사람의 첫 판 이해도, D1 리텐션**: 봇과 시뮬레이터로 만든 추정입니다. 실제 사람 테스트가 필요합니다.
- **글꼴 렌더링 차이**: 게임 글꼴(Jua/Fredoka 일부 글자만 담은 내장 글꼴)은 Chromium에서만 확인.
